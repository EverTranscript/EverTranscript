# 09: M5 close-out — v1 readiness

**What to build:** The evidence that someone who is not the author can install this and understand what it does.

**Blocked by:** 01–08.

Status: three criteria met. **Five are open and every one of them needs a person or a machine this session does not have** — they were briefly ticked by a careless blanket edit and are corrected here, which is exactly the failure mode this project spent five milestones learning to refuse.

- [ ] **A clean-machine install, by someone who did not build it.** Not done, and it is the single most valuable untaken step in the project. Every prior close-out found defects by running the real thing on real input, and every prior set of unit tests had passed. The M5 form is an Operator who is not the author, installing from a package, on a machine that has never built this — and it is the one thing this repository cannot self-serve
- [ ] **Not done.** The Briefing has one job — making a stranger able to say what this product does before they let it record — and nobody but its author has read it
- [x] **Walked, from a genuinely bare state — and getting there found the defect that made it impossible before.** With `EVERTRANSCRIPT_APP_SUPPORT_DIR` set to an empty directory: recording is refused with a message naming the fix, every model reads `missing`, no Backend is chosen. Acknowledging permits recording; choosing `openai` is refused until the warning is accepted; choosing `local` succeeds; and a Meeting records and stops with no models present, which is ADR-0019's degradation working.

  **What it found:** there was no way to isolate Application Support, so models *and* `settings.json` were shared with the developer's machine. A first run on any machine that had ever run this product inherited its acknowledgment — the invariant appeared violated when it was being read from the wrong file. Worse, two guarantee tests set `EVERTRANSCRIPT_MODELS_DIR`, **a variable nothing read**: they copied models where the Core never looked and ran against whatever the machine happened to have. On a runner with none they would have exercised a Core that could not diarize or summarize, found no traffic, and passed — a true sentence about nothing. And the Summary test never generated a Summary at all despite its name. All three fixed.

  Original criterion:
- [x] `a_full_cycle_with_summary_and_updates_off_opens_no_sockets`: acknowledge, choose Local, record, stop, diarize, summarize — and `lsof` reports no sockets on the Core. Skips loudly without models rather than passing quietly. Original criterion:
- [x] **Checked against the built artifact, which is most of it.** Downloaded the macOS zip CI produced, verified its sha256 against the published `SHA256SUMS`, unpacked it, and ran `otool -L` on the Core *inside the bundle*: ScreenCaptureKit, Contacts, MapKit and CoreLocation all absent. The bundled Core also runs from the unpacked artifact (`evertranscript 0.1.0`).

  **What is not checked is the signed case**, because there is no certificate here — codesigning does not add frameworks, so the audit result should not change, but "should not" is the word this project has learned to distrust. Re-run the same two commands against the signed artifact when one exists. Original criterion:
- [x] **Both, and the Windows half found the worst defect of the milestone (Q44).** macOS: installed from the real CI artifact — checksum verified, unpacked, the bundled Core run from it, and `otool -L` showing the permission ledger holds for the artifact rather than the source. Windows: CI's own runner now installs the NSIS package silently and runs what it installed — the Core reports `evertranscript 0.1.0` from `%LOCALAPPDATA%\Programs\EverTranscript`, and the Summary sidecar starts and exits on stdin EOF, **the first time it has executed on Windows at all**. The first attempt failed: `resources\evertranscript.exe` was not in the package. `extraResources` named the macOS filename and electron-builder skipped the missing source in silence, so a hollow 94 MB installer had passed a green matrix and a published checksum. What it did not pass was being installed. Still owed, and not what this criterion asks: an Operator installing on their *own* Windows machine, where the audio stack is real
