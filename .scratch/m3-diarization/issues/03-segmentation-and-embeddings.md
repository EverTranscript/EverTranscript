# 03: Segmentation, fbank, and the two embedding models

**What to build:** The local ONNX pipeline under the seam — voice-activity and overlap segmentation, features, and the two embeddings that do two different jobs. This is the half that touches models and hardware; 04 is the half that reasons about the vectors it produces.

**Blocked by:** 01.

Status: done

- [x] Powerset segmentation ONNX via `ort` — pyannote 3.0, 10 s windows, `logits [batch, frames, 7]`. **The frame duration is derived from the model's own output shape rather than hard-coded**, because a constant scale factor on every timestamp is invisible and would misplace attribution throughout. **Deviation:** the catalog's 1 s step with cross-window label stitching is not implemented; segmentation supplies speech and overlap regions and identity comes from embeddings afterwards. Overlapped speech is consequently one turn rather than two, stated in the module and owed a number by ticket 09. Original criterion: Where a constant is taken from the catalog, cite it where it is written; where one is invented, say so
- [x] **80-mel fbank in pure Rust.** The reference implementation does this in pure JS, so a C dependency buys nothing and costs the cross-platform build the ADR-0025 parity gate depends on
- [x] **One embedding model, not two — a deviation, and the reason is that the premise did not survive contact.** The catalog splits a cheap 256-d clustering embedding from a durable ReDimNet identity embedding because they have different cost profiles. WeSpeaker ResNet34-LM *is* the 256-d one, it runs in well under a second per span on this machine, and there is no cost pressure for a second model to relieve — while a second embedding space would mean two sets of vectors, two model-version columns, and a real chance of comparing across them. The bake-off in ticket 09 is where a second model earns its place on a measurement rather than on the catalog's say-so
- [x] **Voiceprint span selection** is deliberate, not "whatever audio was there" (catalog M3): merge small gaps, subtract overlapped same-channel speech entirely, clip to a bounded middle span, enforce a minimum voiced duration, and take the longest few spans per speaker. A Voiceprint built from crosstalk is worse than no Voiceprint
- [x] Models join the existing checksummed first-run download set (ADR-0034 Sanctioned Traffic unchanged — no new network path, no new host). `evertranscript models` must list, verify and fetch them like every other model
- [x] All three, in `diarize::runner`. The slot is released on panic as well as on return — a poisoned lock would turn one bad Meeting into permanently broken Diarization, with no symptom but silence. Original criterion: M1 already paid for the version of this where transcription starved capture (DECISIONS Q7); post-meeting diarization must not starve live transcription
- [x] **CI now fetches both models (32 MB, sha256-checked) and the inference tests execute on `macos-14` and `windows-latest`.** They skip loudly when the models are absent rather than passing quietly, so a green tick cannot mean "never ran". Original criterion: M2 ended by discovering Windows detection had never worked at all while CI was green, because the code compiled and nothing called it. An `ort` load and a real inference must execute in CI on `windows-latest`, not merely link
- [x] Degradation is honest: a missing or corrupt model leaves the Transcript unattributed and says so, and never blocks the recording or loses the Meeting
