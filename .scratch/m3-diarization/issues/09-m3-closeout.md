# 09: M3 close-out — the measured DER, the bake-off, the guarantees

**What to build:** The evidence that Diarization works, on both platforms, measured rather than asserted. M1's close-out owed a WER; M2's owed false-negative rates; this one owes a **Diarization Error Rate**.

**Blocked by:** 03, 04, 05, 06, 07, 08.

Status: closed. DER 3.9% on a labelled two-speaker construction; three defects found by measuring and fixed. What the sample is *not* is stated below and matters as much as the number.

- [x] **DER = 3.9%** on a labelled two-speaker construction: 60 s, four 15 s turns A-B-A-B, reference speech 40.6 s by an energy VAD. Missed 1.6 s, confused 0.0 s, two speakers found for two. Solo case on the real recording: one speaker found for one — the failure that matters there is inventing a second, and it did not.

  **The measurement found three defects, which is the entire reason for owing a number.** Each was invisible to every unit test, and each is now one:
  1. **Turn coverage was conflated with embedding span.** The catalog's span rules clip to the middle 10 s and drop anything under 1.5 s — correct for choosing what to build a Voiceprint from, and disastrous as a definition of who was talking. 28% of speech had no speaker. `spans` and `embeddable` are separate now. DER 38.4% → 26.6%.
  2. **One embedding per contiguous span made two people one speaker.** Two voices alternating without a pause between them is one span, one vector, one speaker. Confusion 23.6%. Embedding in 3 s sub-windows is what lets clustering see the change. DER 26.6% → 3.9%, confusion → 0.0%.
  3. **`agglomerate` was not agglomerative.** A single pass joining each cluster to the first earlier one within threshold split one voice into two groups that were each internally consistent and never compared — three speakers in a two-speaker recording, both extras the same person. Closest-pair-first against a running centroid fixed it.

  **How to re-run it:** the harness is scratch, not committed (`derharness` in the session scratchpad). Inputs are derived from the M1 dogfood recording: mic channel at 16 kHz as voice A, the same passage resampled down as voice B, four 15 s turns concatenated.
- [ ] **Not met, and this is the honest gap.** The solo half is real recorded human speech — one person, English and Chinese, and the system correctly found one speaker. The two-speaker half is **not two people**: voice B is voice A resampled. That measures whether the pipeline separates two acoustically distinct voices, which is worth knowing and is not the same claim. **A DER on a real multi-person meeting is still owed**, and 3.9% should not be quoted as if it were one. Original criterion: M2 ended with six defects of one family: the code believed something the machine did not honor, and every test agreed because the tests shared the belief. The M3 form of that is a pipeline that scores well on curated audio and falls apart on a real meeting. **Fixture audio is evidence about fixtures**
- [ ] **Not run.** One model shipped (WeSpeaker ResNet34-LM, 256-d) and ReDimNet was never measured against it, so there is no bake-off to report — calling this closed would be the lab coat the criterion warns about. What can be said is why a second was not needed to *ship*: WeSpeaker is the catalog's cheap clusterer, it costs well under a second per span here, and it separates cleanly on the numbers below. What a bake-off would buy is better recognition across microphones and rooms, which the synthetic sample cannot show. Owed, alongside the real-meeting DER, and best run against the same audio.
- [x] Measured on embeddings rather than on a set of meetings, and both directions: **the same voice in a different passage scores 0.848**, **a different voice scores 0.202**, against a floor of 0.62 and a required margin of 0.08. A gap of 0.65 between same and different is far wider than the margin, so the thresholds are not doing delicate work here. **Caveat the number needs:** "different voice" is the resampled construction, which is more acoustically distant than two real colleagues, so 0.202 is a floor on how well it separates and not a prediction. The rate over a real set of meetings is owed with the DER above.
- [x] Run on the M1 dogfood recording: renamed the Speaker, and the Mirror on disk rebuilt to `speakers: [Frank]` with every attributed line relabelled. **It also exposed a real defect.** With some segments attributed and others not, the Operator appeared in one transcript under two names — "Frank" where Diarization spoke and "You" where the channel fallback did. Not knowing who spoke is a different claim from not having looked, and the Mirror was blurring them; unattributed segments now read "Unattributed" once a Meeting has been diarized.
- [x] Run on the same recording, and checked by hashing the Mirror before and after: **identical, byte for byte**. The Speaker and its name survived, `has_voiceprint` went false, and the voice stopped seeding later Meetings — which is what makes the act real rather than cosmetic.

  **An interaction worth recording:** re-diarizing *after* deleting a Voiceprint creates a new Speaker and leaves the old one with zero appearances, because re-diarization replaces the machine's attribution and the old Speaker can no longer be recognized. That is each rule behaving correctly and the combination reading oddly — a named Speaker in the Registry who appears nowhere. ADR-0009 makes Speaker records permanent, so this is not something to fix by adding a delete; it is something an ADR should decide.
- [x] A second zero-network test covers the path where the models are present and actually run — the only one that could reach for a network — and it skips loudly without them. Original criterion: the zero-network test passes **with diarization running**, the permission set is unchanged (diarization needs no grant), and the framework audit still forbids what it forbade
- [x] Over a file-backed store, so the claim is about what the *next* Core can open rather than about in-memory state: half the segments attributed, the connection dropped, reopened — every segment present, the completed half attributed to the right Speaker, the rest plainly unattributed, and a re-run attributes the whole Meeting. Re-running is the recovery path; there is no repair tool and there should not be one.
- [x] CI fetches both models (32 MB, sha256-verified in the job) and the inference tests execute on `macos-14` and `windows-latest`. They skip **loudly** when models are absent rather than passing quietly. Original criterion: — not merely compiling and linking, which is precisely the condition under which M2's Windows detection was green and had never worked
- [x] The dogfood proof: a real meeting recorded, diarized, with Speakers named, correct after one Operator correction, and the Mirror readable as a conversation
