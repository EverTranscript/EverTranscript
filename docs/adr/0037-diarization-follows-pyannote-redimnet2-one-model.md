# Diarization follows the pyannote recipe; ReDimNet2-B3 is its one embedding, self-hosted; a model change re-runs History

> **Amended 2026-09-16 (the embedding clause is withdrawn; the rest stands):** this ADR was never on `main` — it was written on the unmerged branch `diarization-pyannote-redimnet2` while eleven citations to it landed in `main`'s source. It is recorded here so those citations resolve, with the one clause the measurement contradicts withdrawn. **The recipe and the model-change policy stand and have shipped**: segmentation keeps which local speaker holds each frame, each is embedded with the others masked out, overlap produces a turn per speaker, and a model change wipes Voiceprints and re-runs History through a persistent queue (DECISIONS Q133, Q134, Q136). **The choice of ReDimNet2-B3 does not stand as argued.** Its stated ground — "0% cross-meeting EER where WeSpeaker put 15–44% of colleagues above the match floor" — came from a bake-off that ran all three candidates through a front end correct for only one of them (Q111, diagnosed in Q115), so it measured our own feature extraction rather than the models. A committed harness now drives the shipped pipeline with only the embedding moving. On AMI dev, 18 meetings: ReDimNet2 reaches DER 26.01% against WeSpeaker's 29.60%, the whole 3.59-point gap being confusion, so it clusters better inside a meeting; WeSpeaker recognises a returning colleague better, nearest voice right 43.5% against 39.0% and cross-meeting EER 37.74% against 39.18%. Both sit at the same oracle ceiling — 5.56% EER, 90.3% nearest-right — so neither embedding is what bounds the pipeline. **Neither acceptance bar this ADR set is met by either model**: AMI test DER ≤ 18.8% is below the 18.93% oracle floor and so unreachable without changing segmentation rather than the embedding, and cross-meeting EER ≤ 1% against a measured ~38% was a target derived from the same broken bake-off. Which model ships is escalated and open (Q139, superseding Q137); until it is answered WeSpeaker stays, being what is in the build. The thresholds this ADR left as placeholders are still placeholders: Granola's 0.45 / 0.10, confirmed by reading its bundle on 2026-09-16, against our shipped 0.62 / 0.08.

The shipped pipeline scored 49.7% DER on AMI's test set where pyannote publishes 18.8% with the same two models, and about a third of the gap was our own turn placement (DECISIONS Q111, Q112). Decided 2026-09-15, interviewed against Granola 7.515.1's live worker and Swift sidecar and anarlog's `pyannote-local` (`docs/competitive-facts-2026-08-27.md`, corrected the same day): Diarization implements the **pyannote community-1 recipe** that both of Granola's pipelines run — 10 s segmentation windows slid at 1 s, one embedding per local speaker per window, agglomerative clustering, per-speaker reconstruction with overlapping turns and no duration floor — as the same post-meeting Core job on both platforms. The embedding for **both clustering and Voiceprints is ReDimNet2-B3** (PalabraAI, MIT, 192-d, raw 16 kHz waveform in, mel frontend inside the graph), replacing WeSpeaker ResNet34-LM; plain agglomerative clustering, no PLDA. Granola splits the two jobs across a masked WeSpeaker export and ReDimNet2-B3; we take the one model because it measured 0% cross-meeting EER where WeSpeaker put 15–44% of colleagues above the match floor, and because no published ONNX carries the speaker-mask input the masked path needs, so either design ships a self-made export. The export is ours: a committed script under `uv run` with pinned torch, published to a Hugging Face org the product controls — the same host as every other Provisioned Model, so Sanctioned Traffic (ADR-0034) is unchanged. The standard is two measured bars on a committed harness: **AMI test DER ≤ 18.8%** on the shipped path, and **cross-meeting recognition EER ≤ 1%** with no different-colleague pair above the floor.

**A model change discards every Voiceprint and re-runs every Meeting with Kept Audio.** Old and new vectors cannot be compared, and ADR-0035 promised a clean re-embed from kept audio. The upgrade migration nulls every Voiceprint and deletes every exemplar, keeping every Speaker, name and attribution; seeding filters by the current model name as a standing guard. A bulk re-run then walks History oldest first, one persistent queue that a just-ended Meeting or an Operator request enters at the front, pausing while any Meeting records, resuming across restarts, visible and cancellable in the Registry. In each re-run Meeting a *named* Speaker is seeded from its own attributed segments embedded by the new model — the Operator's word about the voice, which ADR-0009 already puts outside the machine's reach — and those windows become its new exemplars. Pseudonymous Speakers are re-minted, so their numbers change. The Operator's Voiceprint is rebuilt by the channel rules alone (ADR-0029 as amended 2026-09-15), never from old attributions. A Meeting without Kept Audio keeps the old run's attributions.

## Considered options

Keep WeSpeaker and add PLDA/VBx (17 to 24 points of clustering error stay); Granola's two-model split (two self-hosted exports, and the masked path is unmeasured here); ReDimNet-B2 (about a point behind B3, no other difference). For the migration: re-embed only the old exemplars' stored sample offsets (rejected: uses the old model's cuts rather than the Operator's confirmation of whole clusters); a wipe with no re-run (rejected: a History nobody is recognized in); keep both vector spaces (rejected: recognition would silently depend on which model heard whom).

## Consequences

- Every installed build pins the export's URL and checksum; publishing it is an outward-facing act that happens once per model, under a written decision, never as a side effect of a build.
- Existing Voiceprints are gone on upgrade. Named Speakers come back as their Meetings are re-run; a named Speaker whose every Meeting lost its audio ends with no Voiceprint and a Registry note saying why.
- The M3 catalog's "reject, don't queue" for batch compute becomes "one queue, the fresh Meeting at the front"; only a Meeting already in line is refused.
- Thresholds (merge, match floor, margin) are re-derived on AMI dev and reported on test through the harness; until then Granola's 0.45 / 0.10 and the bake-off's 0.60 stand as named placeholders.
