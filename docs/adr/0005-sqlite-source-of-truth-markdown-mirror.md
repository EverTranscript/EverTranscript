# SQLite is the source of truth; every Meeting auto-mirrors to Markdown

> **Amended 2026-08-27 (Mirror composition):** one file per Meeting — YAML frontmatter (the UUIDv7 id — its first 8 hex appear in the filename — date, detected app, duration, speaker list) then `# Title`, `## Summary` (ending with Action Items), `## Notes`, `## Transcript` (speaker-labeled and timestamped, reflecting the live join plus correction hints). Skim-first order: the reread material on top, the longest section last. A Mirror exists from the moment the Meeting persists — sections show "None yet" until Summary and Diarization land — and regenerates via the dirty-queue on finalize, Summary generation, retitle, Notes edits, and attribution corrections.

Meetings live in SQLite (with FTS) as the canonical store, and each Meeting is auto-mirrored to a Markdown file in an Operator-visible directory. SQLite gives search and structure; the Markdown mirror keeps the record legible, greppable, and usable without the app — the record is never hostage to the product.
