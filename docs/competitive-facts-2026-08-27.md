Per-product notables:

- **Granola**: ~16 native N-API addons plus dedicated Electron `utilityProcess` children (audio, local ASR, local diarization, SQLite, TCC); encrypted SQLite (better-sqlite3-multiple-ciphers) behind a single `sqlite_process` — single-writer discipline enforced by process boundary; summaries via Granola's own cloud LLM proxy (meeting content leaves the machine); virtual-camera **system extension** (in-meeting watermark), screen OCR of shared screens, global keystroke helper for hotkeys, Zoom/Teams UI automation via Accessibility; models fetched from CloudFront at runtime; not App-Sandboxed; Sentry + Amplitude + Segment + Statsig.
- **anarlog**: Erlang-style actor/supervisor runtime (ractor); embedded two-stage DTLN-style **AEC** + denoiser ONNX + ebur128 loudness; dual-track WAV recording → Ogg Vorbis; sqlx SQLite (62 migrations) + tantivy FTS + CRDT cloud sync (sqlite-sync) + own E2EE layer; **in-process llama.cpp removed** (stubbed) in favor of Ollama / LM Studio / Apple Foundation Models; hosted summaries via OpenRouter (Claude Sonnet); tauri-specta typed IPC; **Windows mic detection is a no-op stub**.
- **Meetily**: `llama-helper` **sidecar** (llama.cpp, JSON over stdio, spawn-on-demand, idle-timeout) for built-in summaries; **bundled ffmpeg** for AAC/mp4 with crash-safe chunk-and-merge recording; RNNoise + ebur128 but **no AEC** (documented Bluetooth/audio-quality complaint class); plaintext API keys in SQLite; GPU support as compile-time cargo features — their top complaint pile; models from Hugging Face + a first-party mirror.
- **codex app-server** (architecture reference, not a competitor): one `MessageProcessor` behind four bindings — spawned stdio child (JSONL), in-process typed channels (their CLIs embed the server), **UDS daemon serving 0..N clients** (0600 socket, startup lock), remote relay; macro-defined protocol tables + ts-rs/schemars codegen with committed, test-enforced fixtures; per-connection initialize + experimental-API gating; thread-scoped vs broadcast fanout with subscription sets and request replay on late attach; **threads keep running at zero clients**; daemon-lifecycle crate is Unix-only; backpressure tuned for interactive traffic (128-message queues, disconnect-on-full).

## Windows support (verified 2026-08-27 where local source can speak)

- **Granola**: a Windows client exists (externally claimed since 2025; not independently verifiable — our artifact is the macOS bundle). But the bundle's **JS is shared across platforms** and carries the Windows paths we already mined: a `win-v2-native` capture manager, WASAPI loopback source-switching with a 20s Teams settle timer, `mic_monitor_v2_process` — **Windows per-process mic-session attribution** with exponential backoff, 6-try give-up, and sibling-cascade detection — and a Windows exe→app mapping table. Only the native layer (capture module, DPAPI credential store) is unmined: JS-architecture facts transfer to their Windows client; native-layer facts do not.
- **anarlog**: shipped — CI builds `x86_64-pc-windows-msvc` plus an NSIS bundle (`desktop_ci.yaml:299-325`, verified), ~19 crates/plugins carry windows-conditional code — but the core feature is hollow there: **Windows mic detection is a no-op stub**, so their meeting-detection prompt never fires on Windows.
- **Meetily**: shipped — `x64-setup.exe` in releases (README:108), live Windows build train in `frontend/` (`build.ps1`, `build-gpu.ps1`, `dev-gpu.ps1`); the `backend/` Windows scripts sometimes cited are the **archived legacy train**, not the shipping path. GPU on Windows is CUDA/Vulkan via compile-time cargo features — their top complaint pile.

Corrections vs 2026-07-09: **anarlog is no longer "thin"** — it ships cross-meeting voiceprints, channel attribution, notes/summaries, a CLI, and an MCP server (though its *local* multi-speaker clustering is a stub; that remains cloud-side, per the 2026-08-27 deep-mine). Our verified differentiators, post-sweep: the **Closed Boundary** (all three ship cloud paths for meeting content), **silent Auto-Record** (anarlog prompts per meeting; Granola leans on calendar + cloud; Meetily CE has none), the **always-on Rust Core daemon + query CLI** (nobody runs a daemon; Granola pays full-Electron-at-login instead), and **working Windows detection** (anarlog's is a stub). Detection-with-local-only-storage remains uncontested.

## Correction, 2026-09-05 — audio timing

`audio/mod.rs` justified absolute capture timestamps partly by asserting that both open-source competitors "omit this and ship an audio-vs-transcript drift that grows with every dropout". The second half does not survive checking: **anarlog works the drift problem, from the other end.** It carries an `audio-sync` crate — `drift.rs` (`LagTrendTracker`, `DriftTrendSnapshot`), `estimator.rs`, `level.rs`, `probe.rs` — that tracks and estimates lag rather than preventing it by stamping frames on a shared capture clock. Two designs with different failure modes, not a presence and an absence.

What still stands, and is the actual argument for our design: a gap must be *explicit* rather than silently shortening the file. Estimation corrects after the fact and degrades with each dropout; a shared monotonic clock makes the gap a fact in the timeline. That claim is about us and needs no competitor to hold.

The claim has been removed from `audio/mod.rs`, which points here instead — a competitive assertion in a code comment cannot be re-verified and rots without saying so. **This is the second under-read of anarlog** (see the "no longer thin" correction above); assume the same of any competitor claim older than a sweep.

Also mined 2026-09-05, not yet acted on: anarlog ships **no ffmpeg** — `hound` (WAV), `vorbis_rs` (Ogg Vorbis), `mp3lame-encoder`, in-process; its `audio-device` crate is device *enumeration* over `cidre::core_audio` (not ScreenCaptureKit), and capture proper lives in `audio-actual`. Its `audio-norm/encode.rs` and `audio-utils/vorbis.rs` are prior art for the codec question reopened in ADR-0032. None of its eleven audio crates are published to crates.io — they are workspace-internal path members, so they are prior art to read, never a dependency (`.scratch/kept-audio-codec/spec.md`).

Adopted implications live in ADR-0027–0032.
